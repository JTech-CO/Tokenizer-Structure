# P1 사용성 검증 프로토콜 — 5분 Learn 경로

- 상태: 프로토콜 확정 / 실제 표본 측정 미실시
- 작성일: 2026-08-25
- 대상 게이트: ROADMAP 11절 "목표 초심자 80%가 5분 경로를 완료", "핵심 4문항 중 3문항 이상 정답 비율 80%"
- 측정 대상 빌드: `docs/P1-VALIDATION.md`에 기록된 artifact revision·engine version과 동일한 배포본

이 문서는 **아직 측정하지 않은 게이트를 언제·어떻게 측정할지**만 고정합니다. 이 문서의 존재는 게이트 통과를 의미하지 않습니다. 측정 결과는 6절 기록 양식으로 남기고, 통과 여부는 `docs/P1-VALIDATION.md`의 남은 게이트 항목에 반영합니다.

## 1. 측정하려는 것과 측정하지 않는 것

측정 대상:

- 외부 설명 없이 5분 경로 6단계를 끝까지 진행할 수 있는가
- 경로를 마친 뒤 해당 경로의 4문항 중 3문항 이상을 맞히는가
- 색상 정보를 사용할 수 없는 조건에서도 차이의 원인을 말로 설명할 수 있는가

측정 대상이 아닌 것:

- 토크나이저 지식 자체의 절대 수준
- 모델·제공사 선호
- 심미적 만족도
- 5분이라는 시간의 엄밀한 준수 (시간은 기록하되 통과 조건이 아님)

## 2. 참가자

목표 사용자 정의 — 다음을 모두 만족하는 사람을 "목표 초심자"로 봅니다.

- LLM 챗봇을 사용해 본 적이 있다
- 토큰·토크나이저·subword·BPE의 의미를 설명할 수 없다고 스스로 답한다
- 본 프로젝트 개발·기획에 참여하지 않았다

표본:

- 최소 10명, 권장 12명. 8명 미만이면 비율을 보고하지 않고 "표본 부족"으로 기록합니다.
- 한국어 사용자와 영어 사용자를 각각 최소 3명 포함합니다.
- 참가자당 3개 경로 중 무작위 배정 1개를 필수로 하고, 남은 시간이 있으면 추가 경로를 선택 진행하게 합니다. 통과율 계산에는 **첫 번째 배정 경로만** 사용합니다.

제외 기준:

- 세션 중 개발자가 힌트를 준 경우
- 앱이 실제 엔진 로드에 실패해 폴백으로만 진행된 경우 (재실시)

## 3. 환경과 사전 조건

- 배포 URL `https://jtech-co.github.io/Tokenizer-Structure/llm_tokenizer_simulator.html`
- 참가자 본인 기기 우선. 최소 1명은 320px 폭 모바일, 최소 1명은 키보드 전용으로 진행합니다.
- 진행자는 화면을 공유받되 조작하지 않습니다.
- 시작 전 확인: 상단 상태가 `실제 엔진`인지, console 오류가 없는지.

진행자가 말해도 되는 것은 다음 세 문장뿐입니다.

1. "이 화면만 보고 5분 학습 경로를 끝까지 진행해 주세요."
2. "생각하는 것을 소리 내어 말해 주세요."
3. "제가 답을 알려드릴 수는 없습니다. 하시던 대로 계속해 주세요."

## 4. 과업

| # | 과업 | 완료 판정 |
|---|---|---|
| T1 | `5분 Learn` 탭으로 이동해 배정된 경로를 연다 | 해당 lesson이 활성 상태 |
| T2 | 학습 목표 → 예측 → 직접 조작 → 규칙 설명 → 오개념 확인 → 한 줄 요약 6단계를 모두 완료 처리한다 | 진행률 6/6 (100%) |
| T3 | 경로가 제시한 예시 입력을 직접 넣고 결과 수치가 바뀌는 것을 확인한다 | 입력 변경 후 수치 변화를 말로 언급 |
| T4 | 4문항에 답한다 | 4문항 모두 응답 |
| T5 | "이 결과가 왜 이렇게 나왔는지" 한 문장으로 설명한다 | 서술 응답 확보 |

경로별 예시 입력은 lesson 데이터에 포함되어 있습니다.

- `token-not-word`: `unbelievable! 안녕`
- `korean-emoji-utf8`: `한글 👩🏽‍💻`
- `same-text-different-tokenizers`: `Hello, tokenizer! 안녕하세요.`

## 5. 채점

### 5.1 경로 완료 (지표 A)

- 완료 = T1~T4를 진행자 개입 없이 끝냄
- 미완료 = 포기, 10분 초과, 또는 진행자 개입 발생
- 통과 기준: 완료자 / 전체 참가자 ≥ 80%

### 5.2 4문항 정답 (지표 B)

각 경로의 문항 ID와 정답은 `js/lessons.js`에 고정되어 있으며 앱의 `scoreLessonQuiz()`가 그대로 채점합니다. 별도 채점표를 손으로 만들지 않고 앱이 반환한 `correct`, `percent`, `passed`를 기록합니다.

| 경로 | 문항 | 정답 |
|---|---|---|
| token-not-word | q1 영어 단어 하나는 토큰 몇 개가 될 수 있나요? | b |
| | q2 구두점은 어떻게 처리될 수 있나요? | c |
| | q3 같은 문장의 토큰 수는 모든 토크나이저에서 같나요? | b |
| | q4 Token ID 42는 모든 모델에서 같은 토큰인가요? | b |
| korean-emoji-utf8 | q1 ASCII 문자 A의 UTF-8 길이는? | a |
| | q2 결합 emoji 하나는 code point 여러 개일 수 있나요? | a |
| | q3 NFC와 NFD 텍스트는 겉모양이 같을 수 있나요? | a |
| | q4 UTF-8 byte 수와 토큰 수는 항상 같은가요? | b |
| same-text-different-tokenizers | q1 같은 문자열이면 Token ID도 모든 토크나이저에서 같나요? | b |
| | q2 공정한 A/B 비교에 필요한 것은? | b |
| | q3 토큰 수가 더 적으면 모델 품질도 반드시 더 좋은가요? | b |
| | q4 휴리스틱 폴백 두 개로 정확한 artifact 차이를 결론 내릴 수 있나요? | b |

- 개인 통과 = 4문항 중 3문항 이상 정답 (`passed === true`)
- 통과 기준: 개인 통과자 / 전체 참가자 ≥ 80%
- 지표 A 미완료자는 **분모에 포함**하고 지표 B는 미통과로 처리합니다. 미완료자를 제외하면 통과율이 부풀려집니다.

### 5.3 색상 비의존 설명 (지표 C)

T5 서술을 다음 루브릭으로 진행자 1명이 채점하고, 서로 다른 2명이 독립 채점해 불일치 시 논의로 확정합니다.

| 점수 | 기준 |
|---|---|
| 2 | 원인을 토큰 경계·byte·정규화·artifact 차이 중 하나로 정확히 지목 |
| 1 | 방향은 맞으나 원인을 색상·"빨간 부분" 등 시각 단서로만 설명 |
| 0 | 설명 불가 또는 잘못된 인과 |

- 통과 기준: 평균 ≥ 1.5 이고 0점 비율 ≤ 10%
- 히트맵을 끈 상태에서도 같은 설명이 가능한지 반드시 한 번 확인합니다.

## 6. 기록 양식

참가자 1명당 한 행. 원문 입력은 기록하지 않습니다.

```csv
participantId,date,locale,device,viewportWidth,inputMode,lessonId,engineMode,
stepsCompleted,taskCompleted,elapsedSeconds,quizCorrect,quizPercent,quizPassed,
narrativeScore,facilitatorIntervened,notes
```

- `participantId`는 익명 일련번호 (예: `P01`). 이름·연락처·이메일을 남기지 않습니다.
- `engineMode`는 `real` 또는 `fallback`. `fallback`이면 해당 행은 통과율 계산에서 제외하고 재실시합니다.
- `notes`에는 막힌 지점과 오해한 표현만 남기고 원문 입력은 남기지 않습니다.

집계 산출물:

- 지표 A/B/C 각각의 비율과 분모
- 미완료 사유 상위 3개
- 문항별 오답률 (오답률 50% 초과 문항은 lesson 문구 수정 후보)

## 7. 개인정보와 동의

- 진행 전 구두 동의를 받고, 화면 녹화 여부를 명시적으로 확인합니다.
- 원문 입력, 이름, 연락처는 수집하지 않습니다.
- 앱은 원문을 브라우저 밖으로 보내지 않으며, 공유 링크 생성은 이 검증 과업에 포함하지 않습니다.
- 기록은 집계 완료 후 원본 녹화를 삭제하고 CSV 집계만 보관합니다.

## 8. 재실시 조건

다음 중 하나라도 해당하면 그 회차 결과를 폐기하고 다시 측정합니다.

- lesson 데이터의 `lessonVersion` 또는 문항이 변경됨
- artifact revision 또는 engine version이 변경됨
- 5분 경로 UI 문구·단계 구조가 변경됨
- 실제 엔진 로드 실패율이 표본의 20%를 초과함

## 9. 결과 반영

측정이 끝나면 다음을 갱신합니다.

1. 이 문서 하단에 회차별 집계표 추가 (표본 수, 지표 A/B/C, 측정일, 대상 revision)
2. `docs/P1-VALIDATION.md` 4절의 사용성 항목을 실제 수치로 교체
3. `ROADMAP.md` Phase 1 완료 조건의 사용성 체크박스 갱신
4. 오답률이 높은 문항은 `js/lessons.js`의 `lessonVersion`을 올리고 근거 URL·검토일을 함께 갱신
